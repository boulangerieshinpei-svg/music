# ボカロ作曲スケッチ

ボカロ曲の**たたき台**を作るためのブラウザアプリ。
作詞・Aメロ／Bメロ／サビの構成・コード進行を**小節単位**で組み立てて、
気に入らない小節だけ AI に書き換えさせる、という作り方ができます。

ビルド不要。`index.html` を開けば動きます。

## できること

| | |
|---|---|
| **セクション構成** | Intro / Aメロ / Bメロ / サビ / Cメロ / Outro を追加・並べ替え・複製・削除 |
| **小節ごとの編集** | 1小節 = コード1つ + 歌詞1行。小節数は自由に増減 |
| **モーラ数の自動カウント** | 拗音は1モーラ、「っ」「ん」「ー」も1モーラで計算。目標モーラとのズレを色で表示 |
| **コードパレット** | 現在のキーのダイアトニック、借用・セカンダリドミナントなどのスパイス、定番進行14種 |
| **鍵盤表示** | 各小節のコードで**どの鍵盤を押さえるか**を表示。音名・度数と、キーの中での役割（`IVM7 サブドミナント` など）も出す |
| **メロディ** | 小節の下のグリッドをタップして音を置く。コードの構成音の行が光るので、そこを叩けば必ずハマる |
| **たたき生成（AIキー不要）** | 雰囲気とセクションの役割から、コード進行・歌詞・メロディのたたきをオフラインで生成 |
| **AIで書き換え** | 小節単位／選択した小節／セクション全体を Claude が書き換え（歌詞・コード・メロディ）。指示文で方向づけできる |
| **移調** | キーを変えると全コードが追従。半音上げ／下げボタンつき |
| **再生** | Web Audio でコードとメロディを一緒に鳴らして確認。伴奏の弾き方（パッド／アルペジオ／刻み）は**小節ごとに変えられる**。クリック付き、パートごとにオフ可 |
| **やり直し** | `↶` `↷`（Ctrl+Z / Ctrl+Shift+Z）。生成し直しや削除も戻せる |
| **ループ再生** | 小節を選んで `▶` すると、その範囲だけ繰り返す。曲全体のループは上部のチェック |
| **スマホ対応** | 1小節を画面幅いっぱいに表示。設定類は畳んで、小節のために画面を空ける |
| **保存・書き出し** | 自動でブラウザに保存。JSON、**MIDI**（DAW向け）、**MusicXML**（Synthesizer V 向け、かな歌詞つき）で書き出し |

## 使い方

```bash
# どれかの方法でローカルサーバーを立てて開く
python3 -m http.server 8000
# → http://localhost:8000
```

ES モジュールを使っているので、`file://` で直接開くとブラウザにブロックされます。
かならずローカルサーバー経由で開いてください。

### 作り方の流れ

1. 上部でキー・BPM・雰囲気・テーマを決める
2. セクションごとに `🎲 コード` でコード進行のたたきを出す（気に入らなければ何度でも）
3. `🎹` でパレットを開き、小節を選んでコードを差し替える
4. `🎲 歌詞` でモーラ数に合う歌詞のたたきを入れる
5. 直したい小節にチェックを入れて、下の指示欄に「もっと切なく」などと書いて `✨ AI歌詞`
6. `🎲 メロディ` でメロディのたたきを出し、小節下のグリッドをタップして直す
7. `▶` で鳴らして確認 → 3〜6を繰り返す

小節右上の `✨` は、その1小節だけを AI に書き換えさせるボタンです。

### メロディの付け方

小節の下のグリッドが、その小節のメロディです。

- **縦** … キーのスケール音（上ほど高い）。**そのコードの構成音の行に色が付く**ので、色の付いた行に置けば外れません
- **横** … 小節の分割（4分／8分／16分。セクションごとに切り替え）
- **タップ** で音を置く／消す。置いた瞬間に音が鳴ります
- **右へドラッグ** で音が伸びます
- PC では**なぞって連続入力**できます

`♪6音` は、その小節に置いた音の数。歌詞のモーラ数と揃うと緑になります
（1音1文字で歌えるということ）。`🎲 メロディ` は、歌詞が入っていればそのモーラ数に音数を合わせて作ります。

音程は「キーのスケール上の段数」で保存しているので、**移調してもメロディがキーに追従**します。

### 高さを変えたいとき

目的によって使う場所が違います。

| やりたいこと | 操作 |
|---|---|
| **曲ごと上げ下げ**したい（歌える高さに合わせる） | 上部の**移調 `▲` `▼`**。半音単位なので、全音上げるなら `▲` を2回。コードもメロディも一緒に動きます |
| **メロディだけ**上げ下げしたい（コードはそのまま） | セクションの `♪▲` `♪▼`（2度＝スケール上で1段）、`♪⇈` `♪⇊`（1オクターブ） |

`♪▲` などは、小節を選んでいれば**その小節だけ**、選んでいなければセクション全体を動かします。

なお、メロディはスケール上の段数で持っているため、メロディだけを厳密に全音（半音2つ）動かすことはできません。
`♪▲` は「スケール上で1段上」なので、キーによって全音になる所と半音になる所があります。
これはキーから外れないための作りです。1音でも音域からはみ出す場合は、形が崩れないよう**何も動かしません**。

### モーラ数の見方

`8 / 7 モーラ` は「今8音、目標7音」の意味。
- 緑 … 目標±1（そのまま乗る）
- 黄 … ±3以内（詰めれば乗る）
- 赤 … それ以上（作り直したほうが早い）

漢字が含まれると読みが確定しないため `⚠` が出て、モーラ数は目安になります。
AI が書いた歌詞は読み（yomi）も一緒に返るので `♪` が付き、正確に数えられます。

## AI機能の設定

⚙ ボタンから Anthropic の API キーを入れると、AI機能が使えるようになります。
キーが無い場合でも `🎲 たたき` 系のボタンはすべて動きます。

**キーの扱いについて:** APIキーはブラウザの `localStorage` に保存され、
リクエストはブラウザから直接 `api.anthropic.com` に送られます
（`anthropic-dangerous-direct-browser-access` を有効にしています）。
**自分のPCで自分のキーを使う前提**のツールです。
共有PCや、誰でも開ける場所にホスティングして使わないでください。

モデルは Opus 5 / Sonnet 5 / Haiku 4.5 から選べます。迷ったら Opus 5。

## 画面の畳み方

作業に必要なものだけ出して、残りは畳んであります。狭い画面ほど効きます。

| ボタン | 何が出るか |
|---|---|
| **曲設定** | キー・移調・BPM・拍子・雰囲気・テーマ・音色・音量・ループなど（スマホでは既定で畳んでいます） |
| **⋯**（セクション） | 目標モーラ・分割・伴奏、AI操作、メロディの上下、鍵盤やパレットの表示、並べ替え・複製・削除 |
| **コンパクト** | 鍵盤や余白を省いて、一度に見える小節を増やします（スマホでは既定でON） |

セクションのヘッダに出しているのは `🎲 コード` `🎲 歌詞` `🎲 メロディ` `▶` の4つだけです。
それ以外は `⋯` の中にあります。

## 詰めるときの操作

### やり直し

`↶` `↷`（**Ctrl+Z** / **Ctrl+Shift+Z**）で戻せます。`🎲` の生成し直し、セクションの削除、メロディの描き直しも全部対象です。
文字入力は1打鍵ずつではなく、少しまとまった単位で戻ります。
歌詞やコードの入力欄にカーソルがある間の Ctrl+Z は、ブラウザの文字取り消し（1文字分）が優先されます。

### ループ再生

- **小節を選んで `▶`** … その範囲だけ繰り返します。「サビの2小節だけ聴きながらメロディを直す」用
- **セクションの `▶`** … そのセクションを繰り返します
- **全体再生** … 上部の「ループ」にチェックを入れると繰り返します
- **スペースキー** … 再生／停止

## コードの読み方を覚える

小節ごとに、そのコードの**鍵盤・音名・度数・キーの中での役割**が出ます（`🎹` で開閉）。

```
[鍵盤]  ← 紫=ルート、青=その他の構成音
F R  A 3  C 5  E M7      ← 音名と、ルートから何度の音か
IVM7  サブドミナント        ← キーの中での位置づけと働き
```

- **度数** … `R`=ルート、`3`=長3度、`♭3`=短3度、`5`=完全5度、`♭7`=短7度。
  同じ形が別のキーでも使い回せると分かるようになります
- **働き** … トニック（安定）／サブドミナント（動き出し）／ドミナント（緊張して戻りたがる）の3種類。
  進行が「なぜ気持ちいいか」はだいたいこの順番で説明がつきます
- **注意書き** … キー外のコードには理由が出ます
  - `セカンダリドミナント（A へ引っ張る）` … 一時的に別のキーのVのように振る舞い、次のコードへ強く進む
  - `サブドミナントマイナー（切なくなる）` … `IV` を短くしたもの。J-POPの切ない場面の定番
  - `借用コード（キー外の響き）` … 同主調などから借りてきた音

**鍵盤をタップするとそのコードが鳴ります。** 形と響きをセットで覚えられます。

音名は理論通りに綴ります（`Fm7` は `F G# C D#` ではなく `F Ab C Eb`）。

## DAW / Synthesizer V へ渡す

作ったたたきを外に持ち出すための書き出しが3つあります。

| ボタン | 形式 | 渡す先 |
|---|---|---|
| **MIDI書き出し** | `.mid` | Studio One などのDAW。メロディとコードの2トラック、テンポ・拍子・調号つき |
| **MusicXML書き出し** | `.musicxml` | Synthesizer V。メロディ＋**1音符1モーラのかな歌詞** |
| **かな歌詞をコピー** | テキスト | 上がうまく行かないときの貼り付け用 |

### 進め方

1. アプリで歌詞・コード・メロディのたたきを作る
2. **MusicXML書き出し** → SynthV で開く（音符と歌詞が一緒に入る）
3. **MIDI書き出し** → Studio One に読み込んでコードとテンポの土台にする
4. SynthV で歌わせて、Studio One で詰める

### 歌詞について

SynthV は MIDI からの歌詞取り込みが不安定なので、**歌詞を渡したいときは MusicXML** を使ってください
（MusicXML の方が歌詞を正確に読めます。ただし日本語での精度は環境によります）。
うまく入らない場合は「かな歌詞をコピー」で、SynthV 側に貼り付けてください。

歌詞は**読みが分かる小節だけ**書き出されます。漢字混じりで読みが未確定の小節は歌詞なしで出力し、
書き出し後のメッセージで「読み不明◯小節」と知らせます。
`✨ AI歌詞` で書いた行は読みも一緒に返ってくるので、そのまま渡せます。
自分で書いた行は、かなで入力するか AI に書き直させると確実です。

書き出し時のメッセージには「◯音中◯音に歌詞」「音数とモーラ数が違う小節◯」も出ます。
数が合っていない小節は、歌詞かメロディのどちらかを直す目印です。

### 制約

- メロディは単旋律として書き出します。同じ位置に複数の高さを置いてある場合は、高い方を残します
- コードトラックはMIDIのみ（MusicXML はメロディだけ。SynthV に渡すため）

## 伴奏の弾き方

パッド（伸ばし）／アルペジオ／刻み の3種類を、**曲 → セクション → 小節** の3段で指定できます。
**下で指定したものが勝つ**ので、普段は曲かセクションで決めておいて、変えたい小節だけ上書きする使い方になります。

| どこで | 操作 |
|---|---|
| 曲全体 | 上部の **音色** セレクト |
| セクション | セクションヘッダの **伴奏** セレクト（「曲に従う」で解除） |
| 小節 | 小節左上の **`パ` `ア` `刻`** ボタン。タップで巡回（上に従う → パッド → アルペジオ → 刻み → 上に従う） |

小節のボタンが薄く表示されているときは、上の指定を引き継いでいる状態です。
小節を複数選んでからボタンを押すと、**選んだ小節をまとめて**変えられます。

## スマホで使う（デプロイ）

GitHub Pages に自動デプロイする workflow（`.github/workflows/deploy.yml`）を入れてあります。
**初回だけ、GitHub 上で2つ設定してください。**

1. **Settings → General → 最下部 Danger Zone → Change repository visibility → Public**
   （Private のまま Pages を使うには有料プランが必要なため）
2. **Settings → Pages → Build and deployment → Source → GitHub Actions**

これで push のたびに自動で反映されます。公開URLは
`https://<ユーザー名>.github.io/music/` です。

スマホでそのURLを開き、ブラウザの「ホーム画面に追加」をすると、
アドレスバーなしのアプリとして起動します（`manifest.webmanifest` を同梱）。

### Public にして大丈夫か

このリポジトリに秘密情報は含まれていません。

- **APIキーはコミットされません。** 各自が画面から入力し、その端末のブラウザの
  `localStorage` にだけ保存されます。リポジトリにもサーバーにも残りません
- **作った曲データもコミットされません。** 同じく localStorage と、手動で書き出す JSON にだけ入ります

公開されるのはアプリのコードだけです。
逆に、URLを知っている人は誰でもアプリを開けますが、**その人が使えるのはその人自身のAPIキーだけ**で、
あなたのキーや曲データが見えることはありません。

### Firebase ではなく GitHub Pages にした理由

このアプリはサーバー処理もデータベースもログインも使わない、完全な静的サイトです。
Firebase を使っても Hosting しか出番がなく、Firestore / Auth / Functions は丸ごと遊びます。
リポジトリが既に GitHub にあるので、Pages なら**アカウントも課金設定も追加せず**に自動デプロイまで済みます。

Firebase（や Cloudflare Workers）を選ぶ意味が出てくるのは、**APIキーをサーバー側に隠したくなったとき**です。
今の作りだとスマホでもキーを1度手入力する必要があります。
これが煩わしい・避けたい場合は、キーを持った中継サーバーを挟む形になります。

なお、リポジトリを Private のままにしたい場合は、Cloudflare Pages や Netlify なら
無料で private リポジトリから自動デプロイできます。

## 制限

- モーラ数は漢字の読みを推測しません（AI が書いた行を除く）
- メロディは1小節の分割（4分／8分／16分）の上に置きます。3連符や細かいタイは表現できません
- メロディはキーのスケール上の音だけを扱います（半音の経過音は置けません）
- 再生音は確認用の簡易なもので、音声の書き出し（WAV）には対応していません
- オフラインでは動きません（Service Worker は入れていません）
